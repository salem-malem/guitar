# Руководство по разработке Guitar

## 📝 Процесс добавления новой фичи

### 1️⃣ Создание Issue

Создайте Issue используя соответствующий шаблон:
- Для фич клиента: **[CLIENT] Название фичи**
- Для фич сервера: **[SERVER] Название фичи**

Шаблоны автоматически добавят нужные labels и чек-листы.

### 2️⃣ Разработка

Работайте в отдельной ветке:
```bash
git checkout -b feature/CLIENT-123-описание
# или
git checkout -b feature/SERVER-456-описание
```

### 3️⃣ Обновление документации

Перед созданием PR убедитесь, что вы обновили:

#### CHANGELOG.md
Добавьте описание под соответствующую секцию `[Unreleased]`:

```markdown
### Client

#### Added
- Новая фича: краткое описание (#123)
```

#### FEATURES.md
Обновите статус фичи (переместите из "Планируется" в "В разработке" или "Реализованные").

### 4️⃣ Pull Request

При создании PR:
- Укажите связанную Issue: `Closes #123`
- Добавьте label: `client` или `server`
- Убедитесь, что CHANGELOG.md и FEATURES.md обновлены
- Пройдите все пункты чек-листа в Issue

### 5️⃣ Код-ревью и мёрж

После одобрения PR можно мёржить. При релизе новой версии секция `[Unreleased]` переименовывается в номер версии.

## 📊 Статусы фич

| Статус | Описание | Файл |
|--------|---------|------|
| 📋 Планируется | Фича в бэклоге, не начата разработка | FEATURES.md |
| 🚀 В разработке | Активная разработка, есть Issue и ветка | FEATURES.md |
| ✅ Реализована | Завершена, слита в master | FEATURES.md + CHANGELOG.md |

---

## 🏷️ Labels для Issues

- `enhancement` — новая фича
- `client` — относится к клиентской части
- `server` — относится к серверной части
- `bug` — баг
- `documentation` — документация
- `integration` — интеграция между client/server

---

## 📦 Релизные версии

Когда вы готовы к релизу:

1. Создайте новую версию в CHANGELOG.md:
```markdown
## [1.0.0] - 2026-05-25

### Client
- Описание...

### Server
- Описание...
```

2. Создайте Release на GitHub с тегом `v1.0.0`

3. Перемещайте завершённые фичи в FEATURES.md в соответствующую версию
